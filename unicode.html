Why do the stored bits differ?

The text character “7” has ASCII code 55, shown as 00110111. The number seven, represented as an eight-bit unsigned integer, is 00000111. The meaning and representation depend on the data type.

Teacher notes, sources & saved work

Lesson 6 follows Character Lab. Together the lessons cover the Characters content of OCR J277 1.2.4: character sets, binary codes and bits versus capacity using ASCII and Unicode. Based on Raspberry Pi’s Lesson 5 and 6 Characters and T3 worksheets, with updated examples and corrected Unicode simplifications.

Original ASCII uses seven bits and 128 codes; OCR displays its binary codes using eight bits. Unicode includes the ASCII characters and a much wider repertoire. Encoding determines the stored bytes; Unicode does not always mean 16 bits. The optional UTF-8 reveal uses fixed single-code-point examples. Complex visible characters can contain multiple code points. See the Unicode encoding FAQ.

Names are represented by the browser; the ASCII-only preview uses a square for unsupported characters. It illustrates a limited character set, not a real file conversion or font test. The free input is limited to 30 code points. Storage exercises use explicit hypothetical bytes-per-character rules, not actual UTF-8 file sizes. The optional text-versus-number activity uses joining rather than claiming all languages treat + the same way.
